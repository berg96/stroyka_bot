## 🔴 Фидбек Артёма вживую (v2 на plitka.mooo.com) — сделать в продолжении
1. **Шов — степпер мёртвый** (нет «−», «+» пустой). Причина: у API НЕТ правки
   `joint_mm` (задаётся только при создании). Починить ПРАВИЛЬНО = добавить правку шва:
   - `storage.py`: метод `set_tile_joint(project_id, tg_id, joint_mm)` по образцу
     `set_tile_size` — пройтись по всем SurfaceRow, `data["tile"]["joint_mm"] = joint_mm`.
     (Шов общий на объект, как и раскладка.)
   - `web/app.py`: в `PatchIn` поле `joint_mm: float | None` (ge=0, le=20); в
     `patch_project` — `if body.joint_mm is not None: await store.set_tile_joint(...)`.
     ⚠️ бот тоже считает шов — проверь, что бот не сломается (он joint не патчит,
     только читает; безопасно).
   - `app.js`: joint-степпер шлёт `livePatch({joint_mm})`, шаги напр. 1 / 1.5 / 2 / 3
     или ±0.5, дефолт из `r.tile.joint_mm`.
   - **Рестарт `stroyka-web`** после (иначе старый бэкенд молча проглотит joint_mm —
     pydantic extra ignore — и шов не изменится). Бэкенд-правки НЕ живые до рестарта,
     это безопасно; фронт живой — верни осторожно.
2. **Ввод значений с клавиатуры, не только ±.** Значение в `stepperRow` (`.cur`)
   должно тапаться и открывать поле ввода (или отдельный лист «введи число»). Касается
   шва, запаса, размера плитки. Идея: `.cur` → `contenteditable`/`<input>` с
   `inputmode=decimal`, на blur/Enter → livePatch с валидацией по min/max.
3. **Схему нельзя посмотреть крупно и скачать.** Схема — герой, но тап по ней ничего
   не делает. Сделать: тап по `.scheme` → полноэкранный вьюер (тёмный backdrop, картинка
   object-contain, pinch-zoom или хотя бы крупно, закрытие по тапу/свайпу). Плюс кнопка
   «Скачать»/«Сохранить». Скачивание в webview Telegram: сперва пробовать
   `tg.downloadFile({url, file_name})` (WebApp API ≥8.0), фолбэк — `<a download>` с
   blob-URL схемы (она уже тянется blob'ом в `loadScheme`). Имя файла — по объекту+стене
   (напр. «Ванная-Стена1.png»). Возможно, отдавать и всю смету-PDF на «Поделиться».

## Осталось — ПРОВЕРИТЬ И ДОЧИНИТЬ (не писать с нуля)
0. **`wrapCtl()` в app.js кривовата** — спека холста должна корректно рисовать сегменты
   (раскладка, смещение только для brick, начало ряда, вид затирки), чипы цвета затирки,
   степперы шва/запаса, тумблеры эконома (только `can_wrap`)/гидро. Тап → `livePatch()`.
1. **`tests/frontend/smoke.js`** — переписать под DOM v2 (портфель→холст, живой пересчёт
   тапом по «Диагональ» шлёт PATCH и обновляет числа, экран вне-Telegram). Прогон:
   `cd tests/frontend && node smoke.js`.
2. `uv run pytest -q` (API не менялся — 196 зелёных) + `uv run ruff check .`.
3. Если smoke зелёный → коммит+пуш, v2 остаётся живой. Если НЕ довести до зелёного →
   откатить 3 статик-файла на v1 (git log; v1 рабочий), закоммитить откат, чтобы живая
   версия не была сломана, оставить заметку тут.

### Историческая справка (как выглядела задача в начале — app.js уже сделан по ней):
   - Экраны: `list` (портфель), `create` (быстрый ввод: имя → режим → стены/высота или
     стена+размер → плитка → «Посчитать»; тонкая настройка свёрнута с дефолтами),
     `canvas` (ГЕРОЙ), `estimate`/`act`, `money`, `price`.
   - **Холст:** схема-PNG сверху (`/api/projects/{id}/scheme/{index}.png`, грузить
     blob'ом с заголовком X-Init-Data — см. `loadScheme` в старом app.js из git),
     табы-миниатюры поверхностей (свайп/тап — **НЕ PATCH**, читаем
     `result.surfaces[index]`), карточка результата (большое «Купить N», kpi упаковки/
     резать), спека с живой правкой.
   - **Живой пересчёт (ядро):** тап по контролу → оптимистично меняем контрол + haptic
     → состояние «считаю» (scheme `.computing` opacity, числа `.computing-dim`) →
     debounce ~120мс, один запрос в полёте, **версия запроса** (игнорить устаревший
     ответ) → `PATCH /api/projects/{id} {поле}` → новый result → кроссфейд схемы + fade
     чисел + haptic success. НЕ звать `run()` изнутри `run()` (баг v1 — вложенный
     глотался; см. коммит про мёртвую кнопку). Отдельный `patchLive()` с дебаунсом.
   - PATCH-поля: `pattern, start_from, offset_label(1/2|1/3|1/4), waste, grout,
     grout_kind, wrap, waterproofing, rotate, tile_size{width_mm,height_mm,kind},
     tile_price`; проём — `POST /opening {surface_id,name,width_m,height_m}`.
   - Видимость: эконом (`wrap`) — только `can_wrap=true`; смещение — только
     `pattern==brick`.
   - Состояния: skeleton при загрузке, пусто (нет объектов / нет поверхностей), ошибка +
     «Повторить», вне Telegram (пустой initData → экран «Откройте через бота»,
     в сервер НЕ стучимся), валидация ввода у поля.
   - Разбор ввода — сервером: `POST /api/measure {kind:walls|height|tile|size, text}`.
   - Смета/акт: `GET /estimate|/act`; смета — материалы НЕ суммируются с работой
     («ВСЁ ВМЕСТЕ ≈»), акт — «ИТОГО К ОПЛАТЕ».
   - Иконки: инлайн SVG Lucide-стиля через `icon(name)`-хелпер (без эмодзи).
   - Кнопка меню/навигация: Telegram BackButton; главное действие — MainButton, где
     уместно (иначе `.dock`-кнопка).
3. **`tests/frontend/smoke.js`** — обновить под новый DOM (портфель→холст, живой
   пересчёт через PATCH, состояние вне-Telegram). Прогон: `cd tests/frontend && node smoke.js`.
4. **Python-тесты**: `uv run pytest -q` (API не менялся — должны быть зелёными, 196).
   Ruff: `uv run ruff check .`.
5. **Деплой:** `systemctl restart stroyka-web` (StaticFiles отдаёт с диска), проверить
   `curl -s https://plitka.mooo.com/ | grep title` и `/api/projects` без подписи → 401.
6. **Коммит + пуш.** Хэндофф `vault/.session/handoffs/stroyka-bot.md` обновить.
