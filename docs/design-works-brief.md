# Бриф Claude Design — расширение мини-аппа на разные виды работ

## 0. Что просим

Сейчас мини-апп считает только **плитку** (готов, «объект-холст»). Расширяем до
сметы на **весь ремонт помещения**: один объект → несколько видов работ → одна смета.
Нужны **hi-fi макеты** новых экранов (плитка уже есть — она референс стиля).

Реализую по макетам я. Бэкенд-модель расчёта на каждый вид опишу и сделаю сам — здесь
она дана, чтобы дизайнер знал, что вводит мастер и что показывать в результате. Не
упрощай до демо: ниже флоу, состояния и модель каждого вида.

## 1. Решения (утверждено Артёмом 18.07)

- **Структура: объект = НЕСКОЛЬКО видов работ в ОДНОЙ смете.** Одна «Ванная» → мастер
  добавляет работы: плитка + сантехника + штукатурка… Замеры комнаты (стены по кругу,
  высота, пол) вводятся ОДИН раз и переиспользуются всеми работами.
- **Виды работ в этой версии:** Плитка (есть) · Штукатурка/шпаклёвка · Ламинат ·
  Плинтус · Откосы · Сантехника. **Обои — НЕ в этой версии** (отложены).
- **Сантехника — список точек × цена** (НЕ детальный конструктор со штробами/трубами).
- **Многокомнатность (проект→комнаты) — НЕ трогаем.** Объект = одна комната.

## 2. Кто пользователь (важно для тона)

Саня — плиточник, тестировал вживую. Его слова (голосовые 17.07):
- **«Зашёл и уже потерялся»** → простота критична, не перегружать.
- Про сантехнику САМ: **«слишком много кнопок, бот заглючит»**, цены индивидуальны
  (штробы в газоблоке ≠ кирпич ≠ монолит) → держим просто.
- Сидит со **старого тормозного Android** → лёгкость, мало ввода, дефолты.
- **«За тебя думает бот»** — идея в том, что мастер вбивает минимум, остальное считается.
- Ориентир, который он назвал: блогер **«Василий Санузел»** — ПК-программа, рисует
  тех.развязки; можно глянуть для вдохновения.

## 3. Платформа / стиль

Как у существующего мини-аппа (он в проде, https://plitka.mooo.com, исходники
`src/tilebot/web/static/`): Telegram Mini App, тема клиента (свет/тьма) через
`--tg-theme-*`, акцент **operation-orange `#ea580c`**, SVG-иконки (не эмодзи),
табличные цифры, нативные MainButton/BackButton/haptic. Новые экраны — в том же языке.

## 4. Модель объекта и главные экраны

### 4.1. Объект с работами (обновление текущего «холста»)
Сейчас объект = сразу расчёт плитки. Станет: объект = **замеры комнаты + список работ**.
- Шапка: название, «N поверхностей · площадь».
- **Замеры комнаты** (свёрнуто): стены по кругу, высота, пол — можно поправить.
- **Работы** — список карточек: вид (иконка), объём (площадь/пог.м/точки), стоимость
  работы. Тап по карточке → экран этой работы.
- **«+ Добавить работу»** → выбор вида (4.2).
- Внизу: **Смета** (общая, 4.4) · Деньги · Прайс.
- Пустое: «Добавь первую работу».

### 4.2. Добавить работу — выбор вида
Крупные карточки-кнопки: Плитка · Штукатурка · Ламинат · Плинтус · Откосы · Сантехника.
Каждая с иконкой и короткой подписью (что считает). Тап → экран ввода вида (4.3).

### 4.3. Экран вида работ (ввод + результат)
Плитка — уже есть (холст со схемой и живой правкой), это **референс**. Остальные виды
проще: без схемы-раскладки, но той же логикой «ввод → мгновенный результат → правка
на месте». Для каждого вида ниже — что вводит мастер, что показать в результате, и как
считается (для дизайнера: какие поля и какие строки итога).

**Штукатурка / шпаклёвка**
- Ввод: поверхность (стены комнаты / потолок / вручную м²), число слоёв (дефолт 1).
- Результат: площадь × ₽/м² (работа) + **смесь** (мешки: расход кг/м² × слои ÷ вес мешка).
- Строки сметы: «Штукатурка стен, X м² × ₽» + «Смесь, N мешков».

**Ламинат**
- Ввод: пол (из замеров комнаты или вручную м²), покрытие пачки (м², дефолт ~2), схема
  (прямая/диагональ/ёлочка → запас 5/12/15%), подложка (да/нет).
- Результат: пачки = ⌈площадь×(1+запас) ÷ покрытие пачки⌉ + подложка (м²).
- Строки: «Укладка ламината, X м² × ₽» + «Ламинат, N пачек» + «Подложка, X м²».
- (Плинтус к ламинату — отдельная работа «Плинтус».)

**Плинтус** (напольный)
- Ввод: периметр пола (из замеров − ширина дверных проёмов) или вручную, длина планки
  (дефолт 2.5 м), тип (ПВХ/МДФ — влияет на цену и фурнитуру).
- Результат: пог.м → штук = ⌈периметр ÷ длина планки⌉ + фурнитура (углы внутр/внешн,
  соединители, заглушки — по числу углов/стыков; дефолт по числу стен).
- Строки: «Монтаж плинтуса, X пог.м × ₽» + «Плинтус, N планок» + «Уголки/заглушки, N шт».

**Откосы** (оконные/дверные)
- Ввод: проёмы (окно/дверь: ширина, высота), ширина откоса (см), материал
  (штукатурка / ПВХ-панель / плитка).
- Результат: на проём периметр откоса (для окна — 3 стороны + низ; для двери — 2 стороны
  + верх) × ширина → м² (штукатурка/плитка) или пог.м (ПВХ-уголок).
- Строки: «Откосы, N проёмов, X м²/пог.м × ₽» + материал.

**Сантехника** (точки — ПРОСТО, по совету Сани)
- Ввод: **чекбоксы точек**: раковина, ванна/душ, унитаз, инсталляция, стиральная машина,
  полотенцесушитель, смеситель, гигиенический душ… Каждая отмеченная = ориентировочная
  цена (из прайса, правится). Плюс поле «прочее, ₽» вручную.
- Результат: сумма отмеченных точек. Строка сметы: «Сантехника: раковина, унитаз,
  стиралка… — N точек, ≈ ₽» (детализация в акте).
- **НЕ делать**: штробы, метраж труб, разводку — Саня прямо просил не усложнять.

### 4.4. Общая смета объекта (все работы)
Сводит ВСЕ работы объекта в один документ (модель денег та же, что сейчас: мастер
продаёт работу, материалы — списком ориентиром, в акте — факт).
- Раздел «Работы» — по каждому виду строка (или подытог).
- Раздел «Материалы — купить» — объединить одинаковые по всем работам (клей, смесь,
  ламинат, плинтус…).
- Итог сметы один — «РАБОТА: ₽» (обновлено 01.08: денег за материалы в смете нет).
  Акт — по факту: плитка по цене мастера, остальное «куплено заказчиком», «ИТОГО К ОПЛАТЕ».

### 4.5. Прайс (расширить)
Добавить расценки под новые виды: штукатурка ₽/м², ламинат ₽/м², плинтус ₽/пог.м,
откосы ₽/м², сантехнические точки ₽/шт (раковина/унитаз/… — свои). Цен на материалы в
прайсе нет (выпилены 01.08). Всё редактируемое, дефолты я проставлю.

## 5. Состояния (нарисовать)
Загрузка (скелетоны), пусто (нет работ), ошибка сервера, вне Telegram, пересчёт
(мгновенный при правке), валидация ввода под полем. Как в текущем мини-аппе.

## 6. Чего НЕ делать
- Не детальную сантехнику (штробы/трубы/разводка) — только список точек.
- **Обои — не в этой версии.**
- Не многокомнатность (проект→комнаты) — объект = одна комната.
- Не перегружать: Саня «теряется», телефон слабый. Минимум ввода, дефолты, «бот думает».
- Не выдумывать материалы/поля вне модели раздела 4.
- Не ломать существующую плитку — она ядро и референс.

## 7. Приоритет
Главное — **экран объекта с работами (4.1)**, **добавление работы (4.2)** и **простые
виды** (штукатурка, ламинат, плинтус, сантехника-точки). Откосы — следом. Плитка не
меняется.

## 8. Формат сдачи
Hi-fi экраны 4.1–4.5 + состояния, светлая и тёмная тема. Плитку показывать не нужно
(готова) — только как ориентир стиля.

## 9. Инженерные заметки (Артёму, не дизайнеру)
Коэффициенты (расход смеси кг/м², покрытие пачки ламината, длина планки, запасы,
цены точек сантехники) — заложу дефолтами, правятся в прайсе. Модель «объект =
несколько работ» потребует правки БД (сейчас объект = один расчёт плитки): добавить
сущность «работа» под объектом. Это то, что раньше откладывали как «дыры в модели» —
теперь делаем, но БЕЗ многокомнатности.
